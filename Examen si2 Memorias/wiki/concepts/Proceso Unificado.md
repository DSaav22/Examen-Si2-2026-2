# Proceso Unificado

Metodología **obligatoria** del parcial. Libro: Booch, Rumbaugh y Jacobson. Canon oral: [[transcripcion-audio-stack-metodologia-parcial]] · resumen: [[stack-metodologia-parcial]].

Garzón lo llama PUDS y pide UML 2.5+ en cada flujo. [[examen1-garzon-fashionstore]]

## Forma (como lo explicó el ingeniero)

Dos ejes del gráfico clásico (pizarra):

1. **Fases:** Inicio → Elaboración → Construcción → Transición.
2. **Disciplinas** (se repiten en cada ciclo): captura de requisitos, análisis, diseño, implementación, pruebas.

Además, analogía con Scrum: en PUD el “sprint” se llama **ciclo** (ciclo 1, 2, 3…) y produce una **versión operativa** (incremento). Eso no sustituye las fases: los ciclos atraviesan el cuadro fase × disciplina.

Para el índice del parcial: estructurar la Parte 2 por **fases**; opcional nombrar iteraciones/ciclos *dentro*. No usar el calendario Scrum (18 sep / 3 semanas) — [[Cronograma]].

La Parte 2 del [[Documento del examen]] es 100% este proceso: no un diario de commits, sino el modelado UP.

## Segundo parcial

El docente lo descarta para el segundo parcial: "no vamos a usar proceso unificado… tampoco Scrum". Se usa [[ICONIX]]. [[transcripcion-audio-segundo-parcial]] Aun así usa la idea de **ciclo** del PU para explicar que el segundo parcial es un incremento. Contraste: [[ICONIX vs Proceso Unificado]].
