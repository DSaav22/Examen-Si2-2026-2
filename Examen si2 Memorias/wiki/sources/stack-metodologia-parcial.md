# Stack y metodología del Primer Parcial

Fuente cruda: `raw/2026-09-12-stack-metodologia-parcial.md`

**Fuente canónica** de tecnologías, PUDS y estructura del informe. Pisa al audio en Flutter/PWA y al PDF de Garzón en FastAPI/Angular/Flutter. Las fechas de sprint (18 sep / 3 semanas) de esta fuente **quedan anuladas** por [[correccion-alcance-parcial]].

## Takeaways

- Stack obligatorio: [[NestJS]] + TypeScript, [[React]], [[React Native]], [[PostgreSQL]] (Azure SQL opcional), deploy en [[Azure]].
- Spring Boot + Angular + Flutter = referencia de *otros* trabajos, no de este parcial. FastAPI queda para microservicios, no para este backend.
- Metodología: [[Proceso Unificado]] (Booch, Rumbaugh, Jacobson). Fases Inicio → Elaboración → Construcción → Transición. En cada iteración: requisitos, análisis, diseño, implementación, pruebas.
- Hay que definir un [[MVP y alcance]] esencial y usable, no “lo más fácil”.
- Informe en 3 partes: teórica, PUDS 100%, adopción/capacitación. Ver [[Documento del examen]].
- Mencionó sprints de 3 semanas y el 18 de septiembre: **no usar**. El hito es el parcial del **23 de septiembre**. [[Cronograma]]
