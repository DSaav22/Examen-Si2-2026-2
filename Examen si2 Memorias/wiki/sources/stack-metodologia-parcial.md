# Stack y metodología del Primer Parcial

Fuente cruda (notas): `raw/2026-09-12-stack-metodologia-parcial.md`  
Transcripción literal de la misma clase: [[transcripcion-audio-stack-metodologia-parcial]] → `raw/2026-09-12-transcripcion-audio-stack-metodologia-parcial.md`

**Fuente canónica** de tecnologías, PUD y estructura del informe. Pisa al audio de e-commerce en Flutter/PWA y al PDF de Garzón en FastAPI/Angular/Flutter. Las fechas de sprint (18 sep / 3 semanas) de esta clase **quedan anuladas para el parcial** por [[correccion-alcance-parcial]].

## Takeaways

- Stack obligatorio: [[NestJS]] + TypeScript, [[React]], [[React Native]], [[PostgreSQL]] (Azure SQL opcional), deploy en [[Azure]].
- Spring Boot + Angular + Flutter = referencia de *otros* trabajos, no de este parcial. FastAPI queda para microservicios, no para este backend.
- Metodología: [[Proceso Unificado]] (Booch, Rumbaugh, Jacobson). Fases Inicio → Elaboración → Construcción → Transición. Disciplinas (requisitos…pruebas) se repiten en cada **ciclo**. El docente igualó oralmente sprint↔ciclo.
- Hay que definir un [[MVP y alcance]] esencial y usable, no “lo más fácil”.
- Informe en 3 partes: teórica, PUD 100%, adopción/capacitación. Ver [[Documento del examen]].
- Mencionó sprints de 3 semanas y el 18 de septiembre (**proyecto semestre**): **no usar** en el parcial. El hito del parcial es el **23 de septiembre**. [[Cronograma]]
