# Ejemplo informe — Tatiana (AutoGo / auxilio vehicular)

Autores: Chavez Melgar Tatiana + Silvestre Carrasco Noelia. Docente: [[Angelica Garzon]]. Gestión 1-2026. Dominio: auxilio vehicular (no moda). Stack del ejemplo: FastAPI + Angular + Flutter + PostgreSQL (otro curso/grupo — **no copiar** a [[EnsayAR]]).

## Estructura del PDF

| Parte | Contenido |
|-------|-----------|
| **I Perfil** | Intro, OG/OE, problema, alcance por capa (móvil/web/API/BD/IA), características, stack, situaciones de uso, consideraciones |
| **II Marco teórico** | Antecedentes int./nac., justificación, cliente-servidor, patrón, metodología, tecnologías, BD, Python/FastAPI, **datos**, **procesos por módulo** |
| **III Proceso** | Flujos UP: **Requisitos → Análisis → Diseño → Implementación → Pruebas** (con **ciclos #1–#3**), no fases Inicio/Elaboración |
| Cierre | Conclusión, recomendación, bibliografía, URL/QR de deploy |

**No trae** Parte “Adopción y capacitación” (eso sí lo pide el docente propio de [[EnsayAR]]).

## Fortalezas (por qué convence)

- Perfil completo + situaciones de uso concretas.
- Marco teórico con antecedentes y justificación (no solo “qué es Nest”).
- CU priorizados + **detallados** (flujos, excepciones).
- Análisis: paquetes, relación paquete↔CU, diagramas de comunicación, análisis de clases por ciclo.
- Diseño de datos **profundo**: clases, mapeo/normalización, volumen, scripts, relacional, consultas, procedimientos, triggers, secuencias.
- Plan y **casos de prueba** extensos (caja negra por CU).
- Evidencia de producto: GitHub + URLs web/móvil.

## Qué no trasladar

Stack FastAPI/Angular/Flutter; dominio grúa/taller; ausencia de Parte 3 adopción; organización por “ciclos” en lugar de Inicio→Transición (canon [[stack-metodologia-parcial]]).
