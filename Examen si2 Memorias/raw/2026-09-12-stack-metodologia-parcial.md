# Stack, metodología y documento — Primer Parcial (docente del curso)

Notas de clase del docente propio. Definen las tecnologías exclusivas del Primer Parcial, el marco de proceso, la estructura del informe y las fechas. Esta fuente manda sobre stack y calendario cuando choca con el audio o con el PDF de Garzón.

## Stack Tecnológico para el Primer Parcial

- **Backend:** NestJS con TypeScript (el docente descartó Python/FastAPI por reservarlo para microservicios y eligió NestJS por su arquitectura modular y empresarial similar a Spring Boot).
- **Frontend Web:** React.
- **Aplicación Móvil:** React Native.
- **Base de Datos:** PostgreSQL (mencionó que es opcional usar el servicio de base de datos SQL en la nube de Azure).
- **Despliegue (Deploy / Cloud):** Microsoft Azure.

Nota: El docente aclaró que el stack previo de Spring Boot + Angular + Flutter era de referencia para otros trabajos, pero para este parcial se evalúa obligatoriamente el ecosistema NestJS + React + React Native.

## Metodología de Desarrollo Obligatoria

- **Marco de proceso:** Proceso Unificado de Desarrollo de Software (UP / RUP) referenciado en el libro de Booch, Rumbaugh y Jacobson.
- **Estructura del ciclo de vida:** Ciclos iterativos e incrementales divididos en las 4 fases clásicas (Inicio, Elaboración, Construcción y Transición) cubriendo los flujos de trabajo de captura de requisitos, análisis, diseño, implementación y pruebas en cada iteración.
- **Alcance del proyecto (MVP):** Cada equipo debe definir su Producto Mínimo Viable (MVP); no se trata de hacer lo más fácil, sino lo estrictamente esencial y funcional para el usuario final.

## Estructura del Documento del Examen (3 Partes)

El informe de entrega debe dividirse obligatoriamente en tres secciones:

1. **Parte 1 – Fundamentación Teórica:** Compilación de conceptos, marcos teóricos e investigación previa sobre las tecnologías aplicadas (e-commerce, realidad aumentada, NestJS, React, etc.).
2. **Parte 2 – Proceso de Desarrollo (100% Proceso Unificado):** Documentación técnica paso a paso de cómo se aplicó el Proceso Unificado (Booch, Rumbaugh, Jacobson) en el proyecto: modelado, análisis, diagramas de diseño, implementación y pruebas.
3. **Parte 3 – Mecanismos de Adopción y Capacitación al Usuario:** Descripción detallada de los métodos o recursos implementados para que el usuario final aprenda a utilizar el sistema sin fricción (manuales, guías interactivas, tutoriales de inducción, etc.).

## Cronograma y Plazos Fijados

- **Duración de cada ciclo/sprint:** 3 semanas por iteración con entrega de una versión operativa (incremento).
- **Fecha de entrega del Primer Sprint:** 18 de septiembre. A partir de esa fecha se contabilizan los ciclos siguientes de 3 semanas.
